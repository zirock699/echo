# Echo Studio engineering quality standards

- **Core experience.** Keep the phrase and main transport dominant. Preserve current playback modes, precise source-cue timing, no startup autoplay, progress semantics and navigation continuity. Give users meaningful feedback when a real operation cannot complete.
- **Change boundaries.** Prefer small repairs to the existing vanilla ESM, CSS and Sites Worker. Trace state ownership before adding another timer, render path, storage flag or abstraction. Apply repo design instructions and protect existing user changes.
- **Playback.** Check clock alignment and actual audio state across seek, replay, speed, lead-in, visibility, source/lesson changes and suspend/resume. Verify the transport through its normal entry points. Distinguish mocked YouTube behavior, real native audio, live YouTube limitations and physical-device observations.
- **Persistence.** Test interrupted operations, offline durability, concurrent revisions and recovery with synthetic data. Preserve old snapshots, stable phrase identities, existing edits and progress. Uncoupled writes require an explicit failure/recovery strategy. Check schema and migration compatibility before proposing rollout. Never test destructive behavior on real data.
- **Security and privacy.** Verify owner isolation, validation, safe rendering, supported origins and device-local recording. Inspect effective hosting security separately from defaults in the repository. Use defensive tests in isolated environments. Maintain normal TLS, signature and integrity verification.
- **UX and accessibility.** Apply `AGENTS.md` and the approved design, start with small mobile sizes and inspect rendered output. Check keyboard/focus, accessible names, status messages, contrast, reduced motion and touch. Capture and open fresh screenshots for visual changes.
- **Testing and acceptance.** Start with an observable success condition and failure cases. Use meaningful regression tests that would fail without the fix. Document commands, outcomes, fixtures, environment and limitations. Prefer existing Node and browser tools. Check the Worker build when relevant. Keep production release validation distinct from local readiness.
- **Done.** The lead verifies requirements and preserved contracts, relevant automated and manual checks, documentation, simplicity and dependency scope, acknowledged residual risk, and an independent review for consequential work. An audit ends with evidence and a priority backlog. Implementation and deployment have their own authorisation.
