## Material findings

### UX-06 · Save & practise returns to Home after creating a lesson

**UX Specialist · import and navigation · Medium · high confidence · confirmed defect.** The core first-practice entry requires an extra action and looks as though practice did not start. The lesson is retained, and Resume lesson recovers the route. This did not reproduce data loss or a playback regression.

**Evidence.** In fresh Chromium at 320 × 568, start on an empty Home, choose Add lessons → YouTube lesson, enter a valid supported URL and two SRT cues starting 1.0 and 4.5 seconds, Preview phrases, then Save & practise. The two preview items appeared and Save enabled. After Save the server snapshot contains one new lesson and the rendered page remains Home. Early exploratory runs from a populated library saw the same route result. In the final empty-library run I logged `pushState` for Home sheet index 1, `back` from the import sheet, then `pop` to Home base index 0. No player entry was committed. Explicit Resume opened the expanded player in that same browser. External blocking affected media availability, while the history trace locates the route failure before a successful media connection is required. [Observed after Save](ux-evidence/first-import-return-home-320-dark.png)

**Cause.** `saveImport` saves the lesson and clears the import modal before `openLesson`. `openLesson` changes the PlayerEngine before assigning `ui.view='player'`. `PlayerEngine.load()` calls `onChange` synchronously. That render temporarily commits the origin view without its sheet. `ScreenHistory.commit` interprets the intermediate key as a request to leave the sheet using `history.back()`, then holds later commits while the pop is pending. The pop restores Home. [Save and open](../../../../src/app.mjs#L247), [open order](../../../../src/app.mjs#L241), [load callback](../../../../src/player.mjs#L107), [navigation commit](../../../../src/navigation.mjs#L10), [restore](../../../../src/app.mjs#L32)

**Remediation and acceptance.** Complete the sheet-to-player transition as one route intent before observer renders commit navigation. Prefer a bounded change to route ownership over a router replacement. Estimate 1–2 engineering days. Moderate risk to Back behavior, startup preparation and compact playback. Coordinate Architect, Playback and QA. A browser regression should start on both empty and populated Home, submit a valid transcript, assert one saved lesson and expanded player for that same ID without autoplay, then press Back and confirm the import sheet stays closed. Test successful save even when the YouTube script cannot connect. **Independent disposition:** submitted for review.

### UX-01 · Player sheets lose keyboard focus

**UX Specialist · accessibility and navigation · Medium · high confidence · confirmed defect.** Keyboard and assistive-technology users lose context when opening the mobile queue, selecting an Options tab with Enter, and closing player sheets. Import preview errors similarly strand focus after rendering the validation message. This contributes to WCAG 2.4.3 focus-order risk.

**Evidence.** Focus Phrase queue and press Enter at 320 × 568. `document.activeElement` is `BODY` while the modal queue is open. Tab then focuses Close queue. Escape again leaves `BODY`. Options initially focuses Close dialog and ArrowRight successfully moves focus to Practice. Pressing Enter on that tab leaves the dialog open with `BODY` focused. Escaping Options or the active word's Pronunciation dialog also returns to `BODY`. On invalid YouTube import preview, the validation message is visible and `activeElement` is `BODY`; the message node has no alert role or live-region attribute. A VoiceOver or TalkBack announcement was not tested. Architecture lane ARC-04 independently found periodic progress saves drop Options focus during active playback. [Focused queue Close after Tab](ux-evidence/queue-320-dark.png)

**Cause.** `render()` replaces the app shell. Most focus and return logic relies on IDs, and triggers/Options tabs have none. The modal-entry rule covers `.modal`, while the mobile queue is a separate `role=dialog` sheet. The existing Tab trap can recover focus only on the next keypress. [Render and restore](../../../../src/app.mjs#L179), [queue markup](../../../../src/app.mjs#L117), [tab action](../../../../src/app.mjs#L339), [trap](../../../../src/app.mjs#L411), [import feedback](../../../../src/app.mjs#L140)

**Remediation and acceptance.** Own initial, retained and returned focus at the sheet boundary. Use stable invoker and control identity where possible, covering pause, render, save, Back and Escape. Surface validation errors programmatically and focus the invalid field or error summary as appropriate. Estimate 1–2 days. Moderate regression risk during app-shell updates and native Back. Coordinate with Architecture ARC-04 and QA. Browser assertions should test initial containment, tab selection and rerenders during paused/playing updates, Escape and native Back returning to surviving invokers, and invalid import field feedback. **Independent disposition:** submitted. Deduplicate against ARC-04.

### UX-03 · Selectable context phrases fall below contrast target

**UX Specialist · accessibility and transcript · Medium · high confidence for the measured fixture · confirmed defect.** Full transcript rows remain controls for choosing a phrase, but distant text is difficult to read while following. The light theme close neighbours broadly maintain readability in the sampled capture. Distant rows fail the project's 3:1 large-text threshold, relevant to WCAG 1.4.3.

**Evidence.** In the 1440 × 900 light fixture, sampled 38px distance-two glyph pixels RGB (149,143,155) and (158,154,165) against nearby backdrop pixels (211,208,214) and (225,224,229). Standard relative luminance yields approximately 2.06:1 and 2.10:1. For comparison, an adjacent row measured 3.41:1 and current phrase ink measured 12.94:1 in the same screenshot. At 390 × 844 Light, computed row opacity was 0.55, 0.35 or 0.24 by distance, and the same visual hierarchy appeared. Pixel samples describe this rendered fixture rather than the range of all possible ambient artwork. [Contrast sample](ux-evidence/player-1440-light.png)

**Cause.** The app sets opacity on the whole row. Every visible selectable line blends with the variable art background, in addition to edge fading on the scroll viewport. Manual browsing raises row opacity, but rows are actionable before manual browsing begins. [Transcript row controls](../../../../src/lyrics.mjs#L14), [opacity rules](../../../../src/mobile-player.css#L24), [contrast contract](../../../../DESIGN.md#L158)

**Remediation and acceptance.** Keep rhythm and hierarchy using weight and contrast-safe color across light and dark ambient palettes. Ensure meaningful visible selectable text, especially when focused or manually browsed, meets 3:1 for large type and 4.5:1 for ordinary type. Estimate 0.5–1 day. Low-to-moderate risk of flattening player hierarchy. UX and QA should verify screenshots and focus readability with dark, light and bright artwork fixtures at small mobile and desktop, comparing current against inactive lines. **Independent disposition:** submitted.

## Bounded follow-ups

### UX-02 · Practice shows duplicate status controls

**UX Specialist · player options · Low · high confidence · confirmed defect.** Options → Practice presents two identical Mark practised/Difficult pairs at 320 × 568, both visible in the screenshot and accessibility tree. That consumes space and doubles navigation stops without adding an action. `optionsSheet()` renders `statusControls` before `practiceForm()`, which renders it again. Keep the single group beside selection. Estimate under 0.5 day and low risk. Coordinate with Playback on preserving both independent flags. Acceptance and browser regression should find exactly one accessible control per mark for the current phrase and confirm each updates independently. [Markup](../../../../src/app.mjs#L120), [rendered duplicate](ux-evidence/practice-options-320-dark.png). **Independent disposition:** specialist reproduction.

### UX-04 · Playback position sheet omits current-phrase time

**UX Specialist · seek UI · Low · high confidence · confirmed defect.** Open Recording timeline from a paused audio player at 320 × 568. The Current phrase slider displays but its time is empty. The full recording row displays `0:05 / 0:40` in the dark example. DOM inspection shows two `phrase-clock` IDs with texts `0:00 / 0:05` and empty string. `updateTimeline` uses `getElementById` and only updates the earlier inline clock. Give each time display unique identity and update both from the existing time source. Estimate under 0.5 day, low risk, dependent on preserving phrase/recording seek semantics. Require a browser assertion that both clocks are legible, advance consistently, and selector IDs remain unique. This finding does not establish incorrect seek behavior. [Inline markup](../../../../src/app.mjs#L106), [dialog markup](../../../../src/app.mjs#L149), [timeline update](../../../../src/app.mjs#L237), [missing time](ux-evidence/clock-detail-320-dark.png). **Independent disposition:** specialist reproduction.

### UX-05 · Settings announces internal preference names

**UX Specialist · accessibility and settings · Low · high confidence · confirmed defect.** In the 390 × 844 AX tree, Practice mode is a combobox named `mode`, Phrase length is `grouping`, Lead-in is `leadIn`, and Speaking pause type is `pauseType`. These labels weaken understanding by a screen-reader user and frustrate a visible-label voice command. Relevant WCAG criterion is 2.5.3 Label in Name. `settings()` builds each select's `aria-label` from the preference key, overriding the surrounding visible label. Use user-facing label text as the accessible name and programmatically associate descriptions separately. Estimate under 0.5 day, low risk. QA should assert that each accessible name includes its visible label and the new naming preserves setting changes. Keep screen awake and Show phrase text already have meaningful names in the current branch. [Settings template](../../../../src/app.mjs#L87). **Independent disposition:** specialist reproduction.

## What to keep and where to invest

Keep the familiar music-player hierarchy, audio-first contrast between lesson types, exact on-screen phrase state, separate mini-player dismissal, distinct primary transport and optional Mirror. Keep the search input's stable identity, conditional See all, accessible text for recovery and internal transcript scrolling. Prioritise the first-use routing failure and focus restoration together as state-transition work. Fix contrast without reintroducing static context panels or extra badges. Consolidate redundant controls locally. Require an actual Android and screen-reader pass before relying on small viewport emulation for an accessibility or mobile release decision.
