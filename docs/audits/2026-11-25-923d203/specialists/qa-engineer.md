## Findings

### QA-01 · Browser suites are out of sync with the UI

- **Owner / domain:** QA Engineer / release verification. **Severity:** Medium. **Confidence:** High. **Classification:** Technical debt with confirmed test failures.
- **Evidence and reproduction:** Run the three local-service suites above against the exact baseline. `browser_navigation.py:26,30–36` and `browser_original_playback.py:34–35` use the old settings/queue selectors. `browser_sync.py:41–43` uses removed timeline/settings selectors. The current gear and footer actions are emitted by `src/app.mjs:96,105–108`. Early test body failures mean later claims cannot be credited. The inlined bootstrap in `tests/browser_smoke.py:9–20` omits current transitive modules from `src/app.mjs:1–20`; the legacy browser startup flags are also unsuitable as a normal-origin gate.
- **Root cause and impact:** UI changes moved controls without maintaining the browser checks. Node tests pass despite breaks in integration coverage. Failures inhibit confidence in a new release and consume diagnosis time. The browser helpers previously claimed in documentation are evidence of a historical run.
- **Remediation, effort and risk:** Refresh tests around accessible names and durable control roles against the actual local module graph. Require assertions after browser navigation settles and drive meaningful slider inputs through keyboard or pointer. Replace obsolete inlined suites with current entry-point examples once their key assertions transfer. About 1–2 engineer days. Low production regression risk because this is test infrastructure. Dependencies are the agreed product contracts, current browser dependencies, and one isolated fixture service per stateful suite.
- **Acceptance / regression checks:** Each maintained browser script exits 0 on a known-good audited baseline using isolated synthetic data and the normal origin security model. A negative control like removing the Save & practise navigation or losing the saved resume state fails the relevant check. Record fixtures, reached assertions and test results by mode. Distinguish real native audio, deterministic IFrame API stubs and real YouTube streaming.
- **Independent validation:** Lead can reproduce from the tracked tests and isolated services. QA did not author these scripts. Reviewer disposition in consolidated report if reviewed.

### Manual Save & practise returns to Home · independent confirmation of UX finding

- **Owner / domain:** UX (cross-validated by QA) / first-use workflow. **Severity:** Medium. **Confidence:** High for active trigger. **Classification:** Confirmed functional defect.
- **Evidence:** Fresh 390 × 844 touch context on disposable localhost with the local IFrame adapter stub. Home Add → YouTube lesson, valid 11-character link, title and two conventional SRT cues → Preview → Save & practise. Two cues previewed. The local server stored exactly one lesson, toast said the first phrase was ready, and route was `#home` with a paused compact player and **Resume lesson**. `#active-phrase` did not exist until Resume. Reproduced in separate fresh services.
- **Root cause:** `saveImport()` closes the sheet before `openLesson()` finishes, and `player.load()` can emit a render before `ui.view` becomes `player`. `ScreenHistory.commit()` then sees the transient Home base route and schedules Back to the stored Home entry. Subsequent commits are suppressed while pending. That event overwrites the desired route. Relevant paths are `src/app.mjs:241,247–248,296–304`, `src/player.mjs:107–124`, `src/navigation.mjs:10–18`.
- **Impact:** The app saves the lesson but requires an extra Resume. This breaks “save and practise” precisely at first success. No loss of the successful import was observed.
- **Remediation / effort / risk / dependencies:** Commit the destination and overlay completion once per successful import, before callbacks can render the previous base route. Keep prior Cancel and ordinary Back behavior. About 0.5–1 day; medium navigation regression risk. Coordinate with the UX lane and architect on the route/render ordering.
- **Acceptance / regression checks:** Fresh empty and existing libraries. Save produces exactly one lesson, closes the import sheet, opens the player on the first cue with no autoplay, stays there after native history events settle, and Back returns to the correct original screen. Cancel saves nothing. Assert the current route as well as data committed, with a mock IFrame interface and no network media.
- **Independent validation:** Reproduced by QA separately from UX. See the UX report for correlation and the consolidated reviewer record for disposition.
