# Product and engineering scorecard

Scores are for the audited baseline and stated conditions. A 0 is missing or unusable, 5 is useful with material gaps, 8 is dependable across demonstrated expected conditions, and 10 requires strong evidence across the supported workflow. Confidence describes breadth and strength of evidence. No combined average is useful because the domains differ in scope and user impact.

| Area | Score | Confidence and evidence | What would raise the score |
| --- | ---: | --- | --- |
| Product coherence | **7/10** | Medium. The audio-first loop, cue control and return journey support repeat practice. Default Continuous is current and deliberate. First import can miss the hand-off into practice and progress labels confuse listening with marks. Learning outcomes are unmeasured. | Open the new lesson reliably, make session and progress meanings honest, simplify existing review and record entry points. |
| Functional completeness | **7/10** | Medium. Major paths exist and current app fixtures exercised import, edit, IPA, course actions, settings and local conflict. Bugs affect valid WebVTT, course Continue and offline startup. | Close confirmed broken normal paths and add targeted current-browser coverage for each. |
| Architecture | **6/10** | High. Stable infrastructure and recognisable module boundaries. Shared mutable lesson state, multiple deletion paths and undifferentiated callbacks weaken consistent transitions. | Give domain mutations and route/focus state explicit ownership. Use a release asset manifest consistent with the app module graph. |
| Code quality | **6/10** | Medium. Tested helpers and adapters coexist with dense action/render code, duplicated branches and manually cached assets. Failures were traced to specific integration points. | Reduce proven duplication and grow focused boundaries during fixes, with readable state transitions and contract tests. |
| Playback reliability | **6/10** | Medium. Local native exact-cue timing, replay/Next and speed checked. One filtered Continuous transition breaks expected completion and Mirror can accept a clipped original. Real YouTube and background physical devices remain unassessed. | Pass mode, seek, resume and media-bounds regressions. Independently measure supported external media and Android. |
| Transcript processing | **7/10** | High for parser and migration behavior in fixtures. Exact cues, rolling-caption correction, partial ZIP salvage and UTF-16 are covered. Valid WebVTT metadata breaks manual preview. | Accept standard metadata, preserve valid/malformed differentiation and verify edit/Undo across current cue shapes. |
| UX/UI | **7/10** | Medium. Clear phrase/transport hierarchy, continuous lyrics, artwork-backed layouts, search and compact player. Important route, clocks and duplicate-actions issues remain. | Fix first practice and test real return/seek workflows with current controls. |
| Mobile usability | **7/10** | Medium. Real rendered 320 × 568 and 390 × 844 player fits and supports fixture playback. Also sampled tablet, landscape and desktop. Physical touch, browser chrome changes and Android background remain unassessed. | Verify physical devices, compact media continuity and accessibility at small sizes and larger text. |
| Accessibility | **5/10** | Medium. Useful native controls, accessible naming in places and reduced-motion behavior were observed. Queue/dialog focus, one transcript contrast state and visible-label mismatches are confirmed. No full assistive-technology or WCAG assessment. | Restore entry/return focus, cover background renders and current names, validate contrast against artwork in both themes and perform assistive-technology checks. |
| Performance | **5/10** | Medium. Small local load and simple Worker. Normal playback repeatedly transfers an approximately 7.13 MB snapshot in the large fixture. Late queue cost spikes with long transcripts. Physical mobile, battery and production network timing are unmeasured. | Coalesce durable progress updates, bound queues, and repeat representative benchmarks and idle checks without losing timing or recovery. |
| Security | **5/10** | Medium for app code. Owner-scoped API checks, bounded media input and clean one-dependency advisory result. Pending mic lifecycle, snapshot markup and cache identity need fixes. Hosted controls unassessed. | Verify cancellation, safe snapshot shape/render, account scope and actual trusted hosting/headers. |
| Data integrity | **6/10** | Medium/high. SQLite migration and compare-and-swap preserve legacy and new snapshots locally. Observed artwork retirement, stale course membership and Undo cursor drop. Restore-to-retired-audio is a conditional risk. | Centralise lesson operations and media references, pass restore and race checks and preserve position and older data. |
| Synchronisation | **6/10** | Medium. Local two-context conflict/recovery and retry are demonstrated. Capacity, identity scope and IDB/cloud failure handling are incomplete. | Keep conflict intent and durable pending data while distinguishing failure modes, capacity and ownership. Verify authorised hosted cross-device behavior. |
| Test coverage | **6/10** | High for observed limits. 170 Node tests passed and meaningful SQLite/clock coverage exists. Current browser scripts have drifted, and several UI and cross-layer invariants are absent from passing automation. | Re-establish executable smoke checks and regression fixtures through current entry points. Cover the priority findings. |
| Deployment reliability | **6/10 local build** | Medium for clean build and packaged routes. Real Sites migration, ingress auth/headers, mobile PWA install and live media remain **not assessed**. | Smoke the built artifact, align app-shell cache with emitted assets, and sign off separately on migration, hosted bindings and identity. |
| Maintainability | **6/10** | Medium/high. Few platform dependencies and good notes on timing decisions. Repeated behavior, stale browser harnesses and cross-layer drift increase change cost. | Adopt the agent workflow and clear ownership, tighten current executable contracts and keep targeted documentation with fixes. |
